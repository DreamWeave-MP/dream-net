# Native transport packaging, CI and licensing

The record for [#13](https://github.com/DreamWeave-MP/dream-net/issues/13): how dream-net and
dream-net-native are packaged, published, gated and redistributed, with the exact commands and
what they did. Everything marked **executed** was run on Linux x86_64 (Bazzite, kernel 7.3.4),
rustc 1.100.0 (LLVM 23.1.5), Clang/LLD 23.1.2, cargo-deny 0.21.0, on 2026-11-18, at the commit
that adds this file or the one before it. Nothing here was run on macOS or Windows, and no
workflow has run on GitHub yet.

## Publishing

| Command | Toolchain | Result (executed) |
| --- | --- | --- |
| `cargo publish --workspace --dry-run` | 1.100 | Pass: packages both, verifies dream-net-native, then dream-net against it through a temporary local registry, aborts both uploads. |
| `cargo publish --workspace --dry-run --locked` | 1.100 | Pass. |
| `cargo +1.88 publish --workspace --dry-run` | 1.88 | `error: the --workspace flag is unstable`. CI never publishes with 1.88 (StroggForge's lint and crates jobs use stable). |
| `cargo publish --dry-run -p dream-net-native` | 1.100 | Pass. |
| `cargo publish --dry-run --manifest-path Cargo.toml` (dream-net alone) | 1.100 | `no matching package named dream-net-native found`: expected until dream-net-native is on crates.io. |
| `publish_workspace.py --list` (StroggForge v55) | | `dream-net-native 0.1.0`, `dream-net 1.1.1` |
| `publish_workspace.py --dry-run` | | `Would publish dream-net-native 0.1.0`; `dream-net 1.1.1 is already on crates.io; skipping` (the version is not bumped yet). |

**Order:** dream-net-native first, then dream-net. **CI:** `ci.yml` now passes
`crate_names: '["dream-net-native", "dream-net"]'` and `cargo_publish_workspace: true`. With that
input StroggForge v55's lint job runs `cargo publish --workspace --dry-run` (which works on stable)
instead of a per-crate dry run that cannot resolve dream-net-native, and on a tag its crates job
runs `publish_workspace.py`, which publishes dream-net-native, waits until the index has it,
then publishes dream-net, skipping versions already there and waiting out rate limits. With only
`crate_names` the tag would also have worked in that order (cargo waits for the index), but the
lint dry run would fail on dream-net every time (it is `continue-on-error`, so it would be
silently red).

Release checklist items that belong to packaging:

1. Bump both versions as the release needs (dream-net-native's only if its contents changed; it
   is new, so 0.1.0 publishes first time) and keep the root's `=` pin equal to it.
2. `cargo publish --workspace --dry-run --locked`, `tools/check-offline-consumer`,
   `tools/check-reproducible`, `cargo deny check`, `tools/check-native-licenses`.
3. If a vendored file, pin or patch moved: `native/tools/verify-vendor --fetch`, regenerate the
   prefix header, redo `native/LICENSES.md`'s review and update `REVIEWED_MATCHES` in
   `tools/check-native-licenses` for any new reviewed match, and keep both NOTICE files byte-equal.
4. Tag; CI publishes dream-net-native then dream-net.

## Offline builds

`tools/check-offline-consumer` (executed, full run, committed tree, `DN_REQUIRE_NETNS=1`):

1. `cargo package --workspace --locked --no-verify`; both tarballs extracted and their file lists
   checked (above).
2. `cargo vendor --locked --versioned-dirs` of the workspace lockfile (the only networked step),
   with both packaged crates added as registry crates (`.cargo-checksum.json` carrying the
   tarball's SHA-256).
3. Then, under `unshare --user --map-root-user --net` (loopback only; the script checks that
   crates.io is unreachable), with an empty `CARGO_HOME` whose only source is that directory,
   `CARGO_NET_OFFLINE=true`, `--frozen`, and a dead HTTP proxy:

| Step | Result |
| --- | --- |
| dream-net-native tarball: `cargo test --frozen` | 82 passed, 1 ignored (the LTO probe) |
| same, `--release` | 82 passed, 1 ignored |
| dream-net tarball: `cargo test --frozen` | 125 passed |
| same, `--release` | 125 passed |
| consumer (`dream-net = "=1.1.1"`, new lockfile resolved offline), debug | client and server exchange Ping/Pong over 127.0.0.1 in ~105 ms: PASS |
| consumer, release | PASS |
| consumer, release, `lto = "fat"`, `codegen-units = 1` | PASS |
| consumer, cross-language LTO: `RUSTFLAGS="-Clinker-plugin-lto -Clinker=clang -Clink-arg=-fuse-ld=lld" DREAM_NET_NATIVE_LTO=full`, fat LTO | PASS; the archive's 6 members are all LLVM bitcode |
| consumer, `CC=gcc` | fails as required: ``the C compiler `/usr/bin/gcc` (from CC) is GCC 16.2, not Clang`` |

The network namespace is the proof that nothing downloads: any fetch would fail rather than be
silently served. strace is not installed here, so connect calls were not traced; with no route
off loopback, none could succeed. What build.rs and the tests run is listed in `native/BUILD.md`
(Requirements); a stripped `PATH` (Clang behind a wrapper, no LLVM binutils) gives the documented
refusals (BUILD.md, Platform matrix).

## Licensing

### Rust: cargo-deny

`deny.toml` (gated by `cargo deny --locked check`, executed: `advisories ok, bans ok, licenses ok,
sources ok`):

- **licenses:** allow MIT, Apache-2.0, BSD-3-Clause, ISC, Unicode-3.0; every other license is
  refused, including GPL, LGPL, AGPL, MPL, SSPL, BUSL/MBSL and non-commercial terms. Dev and build
  dependencies are included (`include-dev`, `include-build`). **MPL-2.0** is refused too: it is
  weak, file-level copyleft and would be lawful to ship, but the campaign rule is no copyleft, so
  it needs a reviewed exception like anything else.
- **bans:** `netcode-official`, `reliable`, `serialize-official`, and `yojimbo`, `yojimbo-sys`,
  `rocketnet`, `rocket-net`, `rocketnet-sys` (cargo-deny matches exact names;
  `tools/check-native-licenses` also refuses any crate whose name contains yojimbo or rocketnet).
  Wildcard requirements are denied (path dependencies inside the workspace exempt).
- **sources:** crates.io only; unknown registries and git sources denied.
- **advisories:** RustSec, nothing ignored. `cargo audit` is also clean (95 crates).

Mutations, each in a scratch copy (executed): adding `reliable = "=1.3.4"` or
`netcode-official = "=1.0.0"` as a dev-dependency fails bans; `buffered-reader` (LGPL-2.0+) fails
licenses; `webpki-roots` 0.22 (MPL-2.0) fails licenses; a git dependency fails sources.

Report only (executed, not gated): `interop/` fails bans on the three ports, as intended (it
compares against them); `fuzz/` fails licenses on `libfuzzer-sys` (`(MIT OR Apache-2.0) AND
NCSA`, permissive) and on its own unlicensed, unpublished crate.

### The C: tools/check-native-licenses

Gates what cargo-deny cannot see (executed: clean). It runs `native/tools/verify-vendor`
(11 files and 1 patch match `PROVENANCE.toml`), requires each upstream's license to be BSD-3-Clause
or ISC and native's `license` to equal `(MIT OR Apache-2.0) AND BSD-3-Clause AND ISC`, scans
`native/vendor`, `native/csrc` and `native/patches` with `native/LICENSES.md`'s forbidden-terms
pattern and allows only the 13 reviewed matches (yojimbo mentions in the shared libsodium subset,
a hash containing `cc0`), requires `LICENSES.md` and `NOTICE.md` to name every vendored file and
`NOTICE.md` to reproduce each upstream text verbatim, requires an MIT OR Apache-2.0 SPDX line in
every file under `native/csrc` and `native/tools`, requires the root `NOTICE.md` to carry every
notice block of `native/NOTICE.md` byte for byte, and refuses the ports and yojimbo/RocketNet
names in `cargo metadata`. Mutations (executed), each caught: GPL text appended to the shim, a
changed vendored file, an extra vendored file, a narrowed license expression, the libsodium
notice removed from the root NOTICE, a vendored file dropped from LICENSES.md, an SPDX line
changed to MPL-2.0.

### The root NOTICE

Someone who takes only the dream-net crate still gets dream-net-native as a dependency, but a
binary redistributor typically collects notices from the crate they depend on, and BSD-3-Clause
requires the notices "in the documentation and/or other materials provided with the
distribution" of every binary. So the root `NOTICE.md` now reproduces every notice verbatim
(netcode, reliable, libsodium ISC, the ChaCha20 public-domain line) rather than pointing at
dream-net-native's, says that any binary built with dream-net must carry it, and keeps the credit
line. `tools/check-native-licenses` keeps the two files byte-identical where they overlap.

**serialize:** no serialize code ships, but `src/bits.rs` reimplements its bit-stream format and
follows its algorithms closely (bit order, alignment, `int_relative`'s buckets) so 1.1.1 peers
interoperate. Whether that makes it a derivative is a legal question; keeping serialize's notice
is the conservative answer and costs nothing, since it is the same Más Bandwidth BSD-3-Clause
text. It stays, explained in the NOTICE.

### Redistribution obligations downstream (l3i, Jess, games)

- **Binaries** (an executable, a shared library, an l3i runtime, a Jess build) that contain
  dream-net must reproduce dream-net's `NOTICE.md` (or dream-net-native's, the same texts) in
  their documentation or accompanying materials: BSD-3-Clause for netcode, reliable and the
  serialize notice, ISC for libsodium. Nothing requires source to be offered; nothing is
  copyleft. The Más Bandwidth names may not be used to endorse the product.
- They must also carry the MIT (or Apache-2.0) notices of the Rust crates compiled in, as for any
  Rust binary: dream-net, dream-net-native and the RustCrypto crates listed above. A tool such as
  `cargo about` generates that file from the crate metadata; the vendored C is invisible to it,
  which is why the NOTICE carries those texts.
- Requested, not required: "netcode - Glenn Fiedler and Rowan Claude", "reliable - Glenn Fiedler
  and Rowan Claude", and the credit line in the NOTICE.
- **Source redistribution** of the crates keeps every file as packaged: the vendored files keep
  their headers, and `LICENSE-*`, `NOTICE.md`, `LICENSES.md` travel with them.

Expected first-run failures and their fixes:

1. **package, network namespace:** Ubuntu 24.04's AppArmor blocks unprivileged user namespaces;
   the job lowers `kernel.apparmor_restrict_unprivileged_userns`. If `unshare` still fails, run
   the offline phase as `sudo unshare --net` or drop `DN_REQUIRE_NETNS` (the script then falls
   back to `--frozen` with a dead proxy and says so).
2. **Windows test job:** first ever compile with clang-cl. Most likely failure: a Windows-only
   warning in our shim under `-WX` (fix the shim), or clang-cl not finding the MSVC headers if
   the image's Visual Studio layout changed (set `INCLUDE` via `vcvars` before cargo).
3. **macOS Intel:** `llvm-ar` absent despite the metadata reading (set `DREAM_NET_NATIVE_AR` in a
   job env or move to StroggForge's later conda setup); Apple's ld64 refusing an object from a
   newer LLVM (would show as a link error in every test binary).
4. **native: LTO probe:** `llvm-objdump` must be on PATH; the job adds Clang's real `bin/` to PATH
   for that. If LLD and rustc disagree on the LLVM major (a new stable on release day before
   apt.llvm.org has it), the probe and the cross-language consumer refuse with the mismatch
   message: rerun when the packages catch up.
5. **sanitizers:** nightly may change `-Zsanitizer` or its runtime; pin a nightly date if it
   breaks.

Not adopted: bumping StroggForge from v55 to v72 (l3i's pin). v72 installs `llvm-N` explicitly,
tests without `--all-targets` and moves Intel to `macos-26-intel` with conda's `nocfg` Clang, but
also changes the site build; that is the director's call with #16.

## build.rs changes

1. **Rerun on the environment cc reads** (`FIX: Rerun the native build when CFLAGS ...`):
   `cargo_metadata(false)` silenced cc's `rerun-if-env-changed` lines, so after a clean build
   `CFLAGS=-ffast-math cargo build` reported the crate fresh and never ran the forbidden-flag
   check (executed before and after: after, it stops). Now declared: the CFLAGS family, cc's
   switches, and what Clang, clang-cl and xcrun read.
2. **Refuse a non-LLVM archiver for Apple targets** (`FIX: Refuse a non-LLVM archiver ...`):
   Apple's ar takes neither `D` nor `--format=darwin`; it is refused before compiling, with what to
   install. Executed as a cross build script run on Linux; on a Mac reasoned.

## Open risks and questions

- macOS and Windows are unverified until CI runs (above). So is Linux aarch64.
- `cc` 1.2.8 is the floor for building; behaviour on Windows and macOS was only exercised with
  the locked 1.11.2 (in CI). A consumer who resolves an old `cc` on those hosts is untested.
- dream-net 1.1.1 is already on crates.io; the version bump and the release decision are the
  director's and the user's.
- `content/docs/compatibility.md` names only netcode, reliable and serialize and their BSD terms;
  it should add the libsodium ISC notice now carried by `NOTICE.md` (site, #16).
- The `REVIEWED_MATCHES` list in `tools/check-native-licenses` must be revisited on every pin move;
  it fails loudly when a reviewed line changes, by design.
